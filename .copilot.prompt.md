Add a `--reset` paramter to `syncript sync` command that will reset the sync state and progress, allowing the user to start a new sync from scratch. When the `--reset` flag is used, the following actions should be performed:
1. Delete the existing sync state file (e.g., `sync_state.csv`) to remove any previously stored state information about the files that have been synced.
2. Delete the existing progress file (e.g., `sync_progress.json`) to remove any information about the progress of the current sync operation.
3. Clear any in-memory state or progress data structures that are being used to track the sync state and progress during the execution of the `syncript sync` command.
4. Do the same action as `syncript sync --push-only` command which will only push the local files to the remote server without performing any pull operations, plus delete any extra files on the remote server that are not present locally. This will ensure that the remote server is in sync with the local files after the reset.
5. Provide appropriate feedback to the user indicating that the sync state and progress have been reset and that a new sync operation will be started from scratch. This can be done by printing a message to the console confirming the reset action and the initiation of a new sync operation. For example: "Sync state and progress have been reset. Starting a new sync operation from scratch..."
6. Ensure that the `--reset` flag can NOT be used in combination with other flags.
